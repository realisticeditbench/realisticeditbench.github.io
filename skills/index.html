pr-subedit-principles

PR Sub-Edit Splitting Principles

Split a PR-level whole.diff into a developer-like, predictable, and verifiable sub-edit sequence. Treat whole.diff as authoritative, plan global step numbers, and choose granularity by semantic predictability — not line count.

  • Authoritative anchor — each file's whole.diff is the single source of truth
  • Four principles — context coherence, atomic intent, logical dependency, cognitive load
  • Global numbering — parallel narratives, continued patterns, definition-before-use
  • Anti-patterns — no import/docs-first steps, no placeholder pass, no oversized hunks

pr-subedit-workflow

PR Sub-Edit Splitting Workflow

End-to-end workflow to convert patch_histories/{instance_id}/ from a PR-level diff into an ordered, strictly validatable sequence. Covers run_split, quick_diff, and sub-edit validation.

  1. A Read global diff and plan the timeline
  2. B Initialize each file from authoritative whole.diff
  3. C Iteratively split with quick_diff --step_index N
  4. D Align local numbers to global step numbers
  5. E Run strict validation via pr_subedit_instance.py
